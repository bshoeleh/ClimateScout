# Deploying Arcadis ClimateScout to IIS

For Arcadis IT and the site owner. The site is an ASP.NET Core (.NET 10) application with a SQL Server database,
hosted in-process on IIS.

## 1. Server prerequisites

- Windows Server with IIS, and the **ASP.NET Core 10 Hosting Bundle** (installs the IIS module; restart IIS afterwards).
- **SQL Server 2019 or later** (the site generates SQL for compatibility level 150).
- An HTTPS certificate for `climatescout.arcadis.com`.

## 2. Folders outside the site

Create these once; deployments never touch them. Give the app pool identity (`IIS AppPool\ClimateScout`) modify rights.

| Folder (example) | Setting | What it holds |
|---|---|---|
| `D:\ClimateScout\media` | `CS__Media__RootPath` | Every image and diagram (`projects/`, `strategies/`, `sponsors/`, `diagrams/`, `other/`). **Back it up with the database.** |
| `D:\ClimateScout\keys` | `CS__DataProtection__KeysPath` | Keys for sign-in cookies; without them everyone is signed out on each restart. |
| `D:\ClimateScout\logs` | (Serilog settings) | Log files, if file logging is configured. |

On the **first** deployment, copy the contents of `wwwroot/img/media/` from the published site into the media folder.
After that, uploads made in Admin go straight there.

## 3. Publish and copy

```
dotnet publish A-U_ClimateScout -c Release -o publish
```

Copy `publish/` to the site folder (e.g. `D:\ClimateScout\site`). `web.config` is generated by the publish.
To deploy an update: stop the app pool (or drop an `app_offline.htm` in the site folder), copy, start it again.

## 4. IIS

- **App pool** `ClimateScout`: .NET CLR version **No Managed Code**, integrated pipeline, *Load User Profile* = True.
- **Site** bound to `https://climatescout.arcadis.com` (port 443) with the certificate; HTTP (80) only to redirect.

## 5. Settings (environment variables on the app pool)

Set them in IIS Manager › the site › Configuration Editor › `system.webServer/aspNetCore` › `environmentVariables`
(so they live in `web.config`'s environment section on the server, not in the code). Secrets go **only** here.

| Variable | Example / notes |
|---|---|
| `ASPNETCORE_ENVIRONMENT` | `Production` |
| `CS__ConnectionStrings__DefaultConnection` | `Server=…;Database=ClimateScout;Trusted_Connection=True;TrustServerCertificate=true` (no `MultipleActiveResultSets`) |
| `CS__AllowedHosts` | `climatescout.arcadis.com` (refuses requests for other host names) |
| `CS__Media__RootPath` | `D:\ClimateScout\media` |
| `CS__DataProtection__KeysPath` | `D:\ClimateScout\keys` |
| `CS__Maps__ContactEmail` | The site owner's email (sent to OpenStreetMap, as its usage policy asks) |
| `CS__Maps__DailyTileCap` / `CS__Maps__DailyGeocodeCap` | Defaults 50000 / 2000; Admins are emailed at 80 % |
| `CS__Email__Host`, `CS__Email__Port`, `CS__Email__UserName`, `CS__Email__Password`, `CS__Email__FromAddress` | Mailjet: `in-v3.mailjet.com`, `587`, API key, secret key, a verified sender address |
| `CS__Email__NotifyAddresses__0` | Who gets contact-form emails (optional; default: every Admin) |
| `CS__ForwardedHeaders__Enabled` | `true` only if the site sits behind a load balancer / reverse proxy |

## 6. Database and first Admin

From the site folder, as a user who can reach the database:

```
dotnet A-U_ClimateScout.dll tool db migrate
dotnet A-U_ClimateScout.dll tool init reference
dotnet A-U_ClimateScout.dll tool init admin --email owner@arcadis.com
```

The last command prints a one-time password; the owner signs in at `/Identity/Account/Login` and chooses their own.
The content itself (zones, strategies, carbon data) is copied from the prepared database or imported with the
`tool import …` commands described in `docs/modernization-plan.md`.

## 7. Check after each deployment

- `/` shows the climate map; `/carbon` the carbon map; a zone page shows its diagram.
- `/admin` asks for sign-in; signing in works and survives an app pool recycle (keys folder in use).
- Response headers include `Content-Security-Policy` and `Strict-Transport-Security`.
- Admin › Dashboard: no unexpected "Needs attention" items.

## 8. Backups

Back up together, nightly: the **database** and the **media folder**. The keys folder only needs copying once
(losing it signs everyone out, nothing more).
